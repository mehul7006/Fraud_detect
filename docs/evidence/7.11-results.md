# 7.11 Protection while FraudShield is closed (swiped away)

Date: 2026-11-22. Android 13 emulator (`test_device`), debug build, backend on `http://10.0.2.2:18080`.

| Step | Result |
|---|---|
| Open FraudShield, log in | dashboard; native copy of the session saved (`fs_background.xml`: API address + token encrypted with an Android Keystore AES-GCM key - stored value does not start with `eyJ`, i.e. not the plain JWT) |
| Swipe FraudShield away in Recents | task gone from Recents, not on screen; the notification listener stays live (`dumpsys notification`: Live notification listeners) |
| Scam SMS arrives (`adb emu sms send`): "Your Paytm KYC is pending. Verify now at http://paytm-kyc-verify.top/login ..." | listener log `background link scan: MALICIOUS`; notification **"Dangerous link!  http://paytm-kyc-verify.top/login  Not using HTTPS, Risky top-level domain .top, Imitates brand 'paytm', Bait words in URL  Do not open it."** visible in the shade |
| Second scam SMS (SBI KYC, raw IP + .apk) | also alerted "Dangerous link!" |
| Account no longer valid (server answers 401) | app returns to the login screen; native copy of the token cleared (0 entries); after a new login it is handed over again |

## Bugs found and fixed while testing
- Server answered **500** (foreign-key error) for a validly signed token whose account no longer exists (deleted account
  or reset DB). Now the JWT filter only accepts tokens of existing users -> **401** (`ApiFlowIT.deleteMe...`).
- The app never reacted to 401: it stayed "logged in" while every call failed. Now a 401 on an authenticated call
  clears the token, shows the login screen and stops background scanning (`app_gate_test`); a 401 from the login
  form (wrong password) is not treated as an expired session.

## Design
Android keeps an enabled NotificationListenerService running by itself, so no extra always-on service was needed.
App on screen -> links go to the app as before (in-app alert); app closed -> `BackgroundScanner` checks them on a
background thread; offline / logged out / server error -> queued for the app as before (nothing lost). Same per-app
switches and trusted sites as the app. WhatsApp/Telegram new-device notices are also reported while closed (feeds 7.2).
Not covered here: periodic heartbeat / forwarding checks while closed (7.6, needs a scheduled job).
