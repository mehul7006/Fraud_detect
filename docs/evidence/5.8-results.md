# 5.8 Storage permission: grant / deny / revoke on Android 10–14

Date: 2026-11-22. Emulators: Google APIs x86_64, Pixel 5 profile, 1.5 GB RAM (Android 13: existing `test_device`, 2 GB).
App: debug APK of the commit that adds `StorageAccess.kt`, backend on `http://10.0.2.2:18080`.
Scripted with `mobile/tool/e2e/test58.sh` (same steps on every version; run one emulator with `run_api.sh <api>`).
"File caught" = a new PDF with `/OpenAction /Launch` written to `Download/` after the permission was given shows up
as a MALICIOUS FILE alert (content flag PDF_LAUNCH, no VirusTotal needed).

| Android | API | Result | Notes |
|---|---|---|---|
| 10 | 29 | 11 / 11 PASS | old runtime storage permission (the bug fixed here) |
| 11 | 30 | 8 / 8 PASS | "All files access" |
| 12 | 31 | 8 / 8 PASS | "All files access" |
| 13 | 33 | 8 / 8 PASS | "All files access" |
| 14 | 34 | 8 / 8 PASS | "All files access"; one "app isn't responding" dialog on the first cold start of the debug build on the software-GPU emulator, Wait pressed, everything passed after it |

## Checks on Android 11–14
1. Fresh install: "Enable file protection" card shown, File protection tile OFF
2. Without permission a new file is NOT scanned
3. "Grant access" opens the system "All files access" page
4. Deny (back without switching on): card stays, tile OFF
5. Grant (switch on, back): card gone, tile ON - refreshed on return, no restart
6. Granted: new file caught
7. Revoked in Settings: card back, tile OFF

## Checks on Android 10 (8–10 path)
1–2 as above, then
3. "Grant access" shows the Android storage permission dialog
4. Deny: card stays, tile OFF
5. Allow: card gone, tile ON
6. Granted: new file caught (proves `requestLegacyExternalStorage` + READ/WRITE_EXTERNAL_STORAGE work)
7. Revoked: card back, tile OFF
8. After a reset the dialog is shown again (the app does not jump to Settings)
9. After the user chose "Don't ask again": "Grant access" opens App info instead of doing nothing
10. Back from App info: card still shown

## Bugs found and fixed while testing
- Android 8–10 always reported file access as granted without asking, so the tile said ON while scanning could not
  read `Download/`. Now READ/WRITE_EXTERNAL_STORAGE (maxSdkVersion 29) are requested at runtime.
- First fix sent users to App info whenever Android said "no rationale", which also happens after a permission
  reset, not only after "Don't ask again". Now the dialog is always tried first and App info opens only when Android
  refuses instantly (< 400 ms = no dialog was shown). `StorageAccessTest` covers both cases.

Not covered: vendor skins (Samsung One UI, Xiaomi MIUI) whose Settings pages look different - check on a real device
before launch.
