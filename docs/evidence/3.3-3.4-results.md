# 3.3 / 3.4 Call-forwarding query on the emulator's SIM

Date: 2026-11-22. Android 13 emulator (`test_device`), simulated SIM "T-Mobile" (gsm.sim.state=LOADED).
The emulator runs the real Android telephony stack (GsmMmiCode -> RIL -> modem); only the network is simulated
(AOSP modem simulator answering `AT+CCFCU`). Evidence = `adb logcat -b radio` + the app's own log.

## What the app received (all four codes are answered)

| Forwarding really | Radio log (network answer) | Text Android gives the app | Android flag `mCallForwarding` |
|---|---|---|---|
| OFF | `status= not active, serviceClass= 0` for reasons 0-3 | `"Call forwarding\n"` | false |
| ON (`**21*<number>#`) | `status= active, reason= 0, serviceClass= 0, number=...` | `"Call forwarding\n"` (same!) | **true** |
| ON (voice class, `**21*<number>*11#`) | `status= active, serviceClass= 0` | `"Call forwarding\n"` | **true** |
| after `##002#` | flag cleared | - | false |

Registration replies seen in the dialer: `"Call forwarding\nRegistration was successful."`.

## Bug found
Android builds the reply text per service class (`Voice: +91...` / `Voice: Not forwarded`). When the network
answers with service class 0, the text is only the header `Call forwarding` - **identical for ON and OFF**.
Text alone can therefore never decide. Before this fix the app showed UNKNOWN for a phone whose calls were really
being forwarded (safe, but the user got no alert).

## Fix
- `CallForwardIndicator.kt` reads Android's public "call forwarding is on" flag (the status-bar icon,
  `TelephonyCallback.CallForwardingIndicatorListener` on 12+, `PhoneStateListener` on 8-11, READ_PHONE_STATE).
- Engine: flag ON -> ACTIVE + alert ("Android also shows its call forwarding icon"), even if the carrier could not
  be asked. Flag OFF does not prove OFF (conditional forwarding never sets it; the emulator showed a network still
  answering "active" with the flag false), so a bare header stays UNKNOWN, never OFF.
- The emulator replies are in `mobile/test/fixtures/ussd_responses.json` with `source: "emulator"` (5 rows); a test
  checks the bare reply is never classified as OFF. 7 new engine tests cover flag ON/OFF/unknown.

## Verified on the emulator after the fix
- Forwarding ON (`**21*<number>#`), app restarted: tile "Call forwarding is ON", alert "Forwarding all calls is active ... (Android also shows its call forwarding icon.)" with "Turn OFF forwarding".
- Tapped "Turn OFF forwarding": app sent `##002#` (radio log `SET_CALL_FORWARD action = 4 cfReason = 4`), flag went false, tile shows UNKNOWN + "Check manually" (bare reply cannot prove OFF - intended).

## Still needed (3.4 gate)
Real carrier wording (Jio / Airtel / Vi / BSNL, often USSD text instead of the Android template, Hindi): only a
phone with a real SIM can give it. Long-press the Call forwarding tile -> Copy; the JSON now also includes the
Android flag.

## Real SIM: Vi India (Xiaomi Redmi Note 12 5G, Android 15 / HyperOS), 2026-11-22
- All four queries answered (network: `status= not active, serviceClass= 255`). Android's reply lists one line per
  service: `Call forwarding\nVoice: Not forwarded\nData: Not forwarded\nFAX: ...\nPAD: Not forwarded`. Tile: **OFF**.
- Phone service switched to Hindi only for the capture (`cmd locale set-app-locales com.android.phone`, reset after):
  `कॉल आगे भेजना\nVoice: अग्रेषित नहीं किया गया\nडेटा: अग्रेषित नहीं किया गया ...` -> was UNKNOWN (bug), now **OFF**
  after rule V8 / app built-in priority 14.
- Found while reading the real format: one forwarded service among "Not forwarded" lines was read as OFF (first
  matching rule won over the whole text). Fixed: per-line classification in app and backend; template rows added.
- Switching forwarding ON was refused by Vi: `**67*<number>#` -> `SET_CALL_FORWARD error MODEM_ERR`; with 4G calling
  the IMS answer was "Connection problem or invalid MMI code" (also with Wi-Fi off). `##02#` is not a valid code
  (clear-all is `##002#`). Jio's own codes (`*401*`, `*405*`, `*413`) only work on a Jio SIM.
- Remaining for the gate: a real reply with forwarding ON from a SIM whose operator allows it.
